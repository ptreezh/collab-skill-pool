# 贡献指南（提交公共技能前必读）

## 一、什么技能适合进公共池

| 适合 | 不适合 |
|---|---|
| 跨企业通用的方法类技能（如「客服话术冷启动」「周报结构模板」） | 含某家企业客户名、合同条款、内部系统的技能 |
| 已脱敏、抽象到可以公开复用 | 原始对话、personal 样本、员工个人经验原文 |
| 有足够样本支撑（`sample_count ≥ 10`） | 只跑过一两次的偶然经验 |
| 明确标注成功/失败类型与适用边界 | 无边界、无来源的泛化结论 |

## 二、提交步骤

1. **Fork** 本仓；
2. 在 `pool/skills/` 新建 `<id>.yaml`（格式见 `docs/skill-card-schema.md`）；
3. 本地校验：
   ```bash
   pip install pyyaml
   python scripts/validate_pool_skill.py pool/skills/sk_xxxxxxxxxxxx.yaml
   ```
4. 发起 PR，按模板填写：样本量、置信度、脱敏确认、来源说明；
5. 等待维护者审核（建议 5 个工作日）；
6. 合并后维护者将 `status` 置为 `approved`，全量用户下次 `pool-pull` 生效。

## 三、脱敏自查清单（逐条确认）

- [ ] 无真实客户名、公司名、人名
- [ ] 无手机号、身份证号、邮箱、地址
- [ ] 无账号、令牌、密钥、内网 IP、内网域名
- [ ] 无原始对话记录、无 personal 样本
- [ ] 无未公开的业务数据、价格政策、合同条款
- [ ] `skill_text` 已抽象为可公开复用的规则/提示词
- [ ] `source_note` 只写脱敏来源类型，不写具体客户

## 四、撤回

技能作者可随时发起 PR，将 `status` 改为 `deprecated` 或请求删除该卡；维护者核实后合并。

## 五、审核关注点

维护者会重点核对：
1. 是否满足门槛（sample≥10、confidence≥0.6，PR 描述注明）；
2. 是否明显泄露敏感信息（CI 粗筛 + 人工复核）；
3. `fingerprint` 是否与池内既有卡冲突；
4. `apply_expert_ids` 是否与现有专家匹配（不匹配的技能应写清适用专家类型）。
